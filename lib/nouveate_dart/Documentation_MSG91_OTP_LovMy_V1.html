Présentation

Ce document décrit l'intégration complète du service MSG91 OTP Widget dans l'écosystème LovMy, pour sécuriser l'inscription et la connexion des utilisateurs par vérification du numéro de téléphone.

Périmètre
  • API d'authentification Laravel 12 (backend, monorepo Prj_LovMy)
  • Application mobile Flutter (écrans numéro / OTP)
  • Configuration du compte et du Widget MSG91
  • Environnements staging (dontmove.app) et production (lovmy.fr)
Public visé
  • Développeurs backend Laravel travaillant sur l'API /api/v1/auth
  • Développeurs Flutter en charge du flux d'inscription/connexion
  • Toute personne amenée à administrer le compte MSG91 de LovMy
Pourquoi MSG91 ?

MSG91 fournit un widget OTP prêt à l'emploi (envoi SMS, gestion des tentatives, renvoi, expiration) sans avoir à opérer notre propre passerelle SMS. Il est mutualisable avec les autres produits MSG91 déjà utilisés dans l'écosystème Don't Move (Email, WhatsApp, Campaign).

Architecture de l'authentification LovMy

Le flux d'authentification repose sur trois acteurs : l'application Flutter, l'API Laravel 12 et le service MSG91. Laravel ne stocke jamais l'OTP en clair et ne fait jamais confiance à un OTP validé côté client : la vérification finale passe toujours par MSG91.

Principes clés

  • Stateless côté Laravel — l'état de l'OTP (code, expiration, tentatives) est délégué à MSG91 via son Widget ID. Laravel journalise seulement les tentatives (numéro, horodatage, résultat).
  • Un seul point de vérité — la vérification finale du code se fait toujours via l'appel serveur-à-serveur à MSG91 (jamais uniquement côté mobile).
  • Session émise uniquement après succès — le token Sanctum (ou JWT) n'est généré qu'après une réponse success de MSG91.
  • Idempotence — un compte existant se reconnecte via le même flux ; un nouveau numéro déclenche la création de compte après vérification.
03 / 21

Création du compte MSG91

  1. Créer un compte sur control.msg91.com avec l'adresse contact@lovmy.fr.
  2. Renseigner les informations de l'entreprise (Full IT / LovMy) et valider l'e-mail professionnel.
  3. Compléter le KYC si demandé (nécessaire pour lever certaines limites d'envoi SMS).
  4. Depuis le menu principal (icône grille en haut à gauche), sélectionner le produit OTP dans la section « Products ».
  5. Créditer le compte via Add Funds pour permettre l'envoi de SMS en production.
  6. Ajouter les membres de l'équipe technique via Manage Members avec des rôles restreints (lecture seule pour la majorité, admin pour le CTO).
Repères dans le dashboard

Le compte LovMy apparaît sous l'espace de travail full11. Le sélecteur « Select Service → OTP Widget » permet de basculer entre les produits MSG91 (Campaign, Hello, Segmento, OTP, One API) sans changer de compte.

04 / 21

Configuration complète du Widget OTP

Le Widget OTP centralise la logique métier de l'OTP (génération, expiration, tentatives, renvoi). Il se configure une fois puis se réutilise pour tous les environnements via son WIDGET_ID.

  1. Dans OTP → OTP Widget, cliquer sur Create Widget.
  2. Nommer le widget de façon explicite par environnement : LovMy Production et LovMy Staging (deux widgets distincts recommandés pour isoler les quotas et les logs).
  3. Longueur de l'OTP : 6 chiffres (équilibre sécurité / ergonomie mobile).
  4. Expiration : 300 secondes (5 minutes).
  5. Nombre de tentatives de saisie : 3.
  6. Nombre de renvois autorisés : 2, avec un délai minimal de 30 secondes entre deux renvois.
  7. Canal actif : SMS uniquement (WhatsApp et Voice désactivés pour ce widget — gérés séparément si besoin).
  8. Associer le Sender ID et le(s) template(s) créés aux sections 5 et 6.
  9. Enregistrer, puis copier l'AUTH KEY (Settings → Authkey) et le WIDGET ID généré.
Point de vigilance

L'AUTH KEY est un secret global au compte (pas seulement au widget). Il ne doit jamais être committé dans le dépôt Git ni exposé côté Flutter — il reste exclusivement côté serveur Laravel, dans le fichier .env.

# .env
MSG91_AUTH_KEY=xxxxxxxxxxxxxxxxxxxxxxxx
MSG91_WIDGET_ID=xxxxxxxxxxxxxxxxxxxxxxxx
MSG91_SENDER_ID=LOVMY

Création des Templates SMS

Le template définit le texte exact envoyé par SMS. Il doit être approuvé par MSG91 avant utilisation en production.

LovMy
Votre code de vérification est : {{OTP}}
Valable 5 minutes.
Ne partagez jamais ce code.

Multilingue (15 langues)

Conformément à l'ouverture internationale de LovMy, un template est décliné pour chaque langue supportée (FR, EN, ES, AR, PT, IT, DE, NL, RU, TR, SW, HA, WO, YO, ZH). Les traductions sont réalisées via DeepL puis relues par un locuteur natif avant soumission.

  • Le placeholder {{OTP}} doit rester identique dans toutes les langues.
  • Chaque template est soumis séparément à validation MSG91 (délai habituel : quelques heures à 24h).
  • La langue envoyée est déterminée par la locale de l'appareil Flutter, transmise dans le corps de la requête send.
Bon à savoir

Selon les pays ciblés, certains opérateurs exigent un enregistrement réglementaire du template (équivalent DLT en Inde). Pour la Côte d'Ivoire et la zone UEMOA, aucun enregistrement DLT n'est requis, mais MSG91 impose sa propre validation de contenu.

Configuration des Sender ID

Le Sender ID est le nom affiché comme expéditeur du SMS (ex. LOVMY au lieu d'un numéro).

  1. Dans SMS → Sender ID, demander la création d'un Sender ID alphanumérique LOVMY (6 caractères max recommandé).
  2. Fournir les justificatifs demandés par MSG91 (nom de marque, capture de l'app ou du site).
  3. Attendre la validation (statut visible dans le dashboard, généralement 24–48h).
  4. Associer ce Sender ID au Widget OTP créé en section 4.

Intégration Laravel 12

Aucun package tiers n'est nécessaire : l'appel à l'API MSG91 se fait directement via le client HTTP natif de Laravel (Illuminate\Support\Facades\Http), déjà basé sur Guzzle.

  1. Vérifier la présence de guzzlehttp/guzzle dans composer.json (inclus par défaut avec Laravel 12).
  2. Créer le service dédié app/Services/Msg91OtpService.php (section 9).
  3. Créer le contrôleur app/Http/Controllers/Api/Auth/OtpController.php (section 10).
  4. Déclarer les routes API sous /api/v1/auth/otp/* (section 11).
  5. Créer les Form Requests de validation (section 12).
  6. Ajouter un canal de log dédié otp (section 14).
  7. Publier la configuration : php artisan config:cache après chaque modification du .env en production.

Service Msg91OtpService

Ce service encapsule tous les appels HTTP vers MSG91 et normalise les réponses.

<?php

namespace App\Services;

use Illuminate\Support\Facades\Http;
use Illuminate\Support\Facades\Log;
use App\Exceptions\OtpException;

class Msg91OtpService
{
    protected string $authKey;
    protected string $widgetId;
    protected string $baseUrl;

    public function __construct()
    {
        $this->authKey  = config('services.msg91.auth_key');
        $this->widgetId = config('services.msg91.widget_id');
        $this->baseUrl  = config('services.msg91.base_url');
    }

    /**
     * Envoie un OTP au numéro fourni.
     */
    public function send(string $phone, string $locale = 'fr'): array
    {
        $response = Http::withHeaders(['authkey' => $this->authKey])
            ->asForm()
            ->post("{$this->baseUrl}/otp", [
                'widget_id'    => $this->widgetId,
                'mobile'       => $phone,
                'template_lang' => $locale,
            ]);

        Log::channel('otp')->info('otp.send', [
            'phone'  => $this->maskPhone($phone),
            'status' => $response->status(),
        ]);

        if (! $response->successful() || ($response->json('type') ?? 'error') !== 'success') {
            throw new OtpException(
                $response->json('message', "Échec de l'envoi de l'OTP"),
                $response->status()
            );
        }

        return $response->json();
    }

    /**
     * Vérifie l'OTP saisi par l'utilisateur.
     */
    public function verify(string $phone, string $otp): bool
    {
        $response = Http::withHeaders(['authkey' => $this->authKey])
            ->get("{$this->baseUrl}/otp/verify", [
                'mobile' => $phone,
                'otp'    => $otp,
            ]);

        $success = $response->successful()
            && ($response->json('type') ?? 'error') === 'success';

        Log::channel('otp')->info('otp.verify', [
            'phone'   => $this->maskPhone($phone),
            'success' => $success,
        ]);

        return $success;
    }

    /**
     * Déclenche un renvoi d'OTP (SMS uniquement pour LovMy).
     */
    public function resend(string $phone, string $retryType = 'text'): array
    {
        $response = Http::withHeaders(['authkey' => $this->authKey])
            ->get("{$this->baseUrl}/otp/retry", [
                'mobile'     => $phone,
                'retrytype'  => $retryType,
            ]);

        if (! $response->successful()) {
            throw new OtpException("Échec du renvoi de l'OTP", $response->status());
        }

        return $response->json();
    }

    protected function maskPhone(string $phone): string
    {
        return substr($phone, 0, 4) . str_repeat('*', max(strlen($phone) - 6, 0)) . substr($phone, -2);
    }
}

Contrôleurs

<?php

namespace App\Http\Controllers\Api\Auth;

use App\Http\Controllers\Controller;
use App\Http\Requests\Auth\SendOtpRequest;
use App\Http\Requests\Auth\VerifyOtpRequest;
use App\Services\Msg91OtpService;
use App\Models\User;
use App\Exceptions\OtpException;
use Illuminate\Support\Facades\RateLimiter;

class OtpController extends Controller
{
    public function __construct(protected Msg91OtpService $otp) {}

    public function send(SendOtpRequest $request)
    {
        $key = 'otp-send:' . $request->phone;

        if (RateLimiter::tooManyAttempts($key, 5)) {
            return response()->json([
                'message' => 'Trop de demandes. Réessayez plus tard.',
            ], 429);
        }

        RateLimiter::hit($key, 60); // 5 envois / minute / numéro

        try {
            $this->otp->send($request->phone, $request->locale ?? 'fr');

            return response()->json(['message' => 'Code envoyé.']);
        } catch (OtpException $e) {
            return response()->json(['message' => $e->getMessage()], 422);
        }
    }

    public function verify(VerifyOtpRequest $request)
    {
        $verified = $this->otp->verify($request->phone, $request->code);

        if (! $verified) {
            return response()->json(['message' => 'Code invalide ou expiré.'], 422);
        }

        $user = User::firstOrCreate(
            ['phone' => $request->phone],
            ['phone_verified_at' => now()]
        );

        $user->forceFill(['phone_verified_at' => now()])->save();

        $token = $user->createToken('lovmy-mobile')->plainTextToken;

        return response()->json([
            'token' => $token,
            'user'  => $user,
        ]);
    }

    public function resend(SendOtpRequest $request)
    {
        try {
            $this->otp->resend($request->phone);

            return response()->json(['message' => 'Code renvoyé.']);
        } catch (OtpException $e) {
            return response()->json(['message' => $e->getMessage()], 422);
        }
    }
}

Validation des Request

<?php

namespace App\Http\Requests\Auth;

use Illuminate\Foundation\Http\FormRequest;

class SendOtpRequest extends FormRequest
{
    public function authorize(): bool { return true; }

    public function rules(): array
    {
        return [
            'phone'  => ['required', 'string', 'regex:/^\+?[1-9]\d{7,14}$/'],
            'locale' => ['sometimes', 'string', 'size:2'],
        ];
    }

    public function messages(): array
    {
        return [
            'phone.regex' => 'Le numéro de téléphone doit être au format international (ex. +2250700000000).',
        ];
    }
}
<?php

namespace App\Http\Requests\Auth;

use Illuminate\Foundation\Http\FormRequest;

class VerifyOtpRequest extends FormRequest
{
    public function authorize(): bool { return true; }

    public function rules(): array
    {
        return [
            'phone' => ['required', 'string', 'regex:/^\+?[1-9]\d{7,14}$/'],
            'code'  => ['required', 'digits:6'],
        ];
    }
}

    }

Bonne pratique

Ne jamais renvoyer au client le message d'erreur brut de MSG91 (il peut révéler des détails internes). Toujours passer par un message générique côté API, tout en journalisant le détail réel côté serveur.

  • Chaque tentative de vérification échouée est loguée avec l'IP source pour détection d'abus.
  • Rotation quotidienne, rétention 30 jours, conforme à la politique de logs Full IT.
15 / 21

Sécurité

Côté serveur
  • HTTPS obligatoire sur tous les endpoints d'authentification.
  • AUTH_KEY stockée uniquement en variable d'environnement, jamais en base ou en dur.
  • Rotation de l'AUTH_KEY tous les 6 mois ou en cas de suspicion de fuite.
  • Validation stricte du format du numéro avant tout appel MSG91 (évite les envois vers des numéros invalides, facturés inutilement).
Côté mobile (Flutter)
  • Le token de session est stocké via flutter_secure_storage, jamais en SharedPreferences brut.
  • Aucun secret MSG91 n'est présent dans le bundle mobile.
  • Le champ OTP est masqué à l'écran (option d'affichage temporaire uniquement).
Rappel

La vérification de l'OTP doit toujours transiter par le backend Laravel. Une application mobile ne doit jamais appeler directement l'API MSG91 avec l'AUTH_KEY.

Rate Limiting

En complément des limites imposées par le Widget MSG91 (3 tentatives, 2 renvois), Laravel applique ses propres garde-fous.

// app/Providers/AppServiceProvider.php (méthode boot)
use Illuminate\Cache\RateLimiting\Limit;
use Illuminate\Support\Facades\RateLimiter;
use Illuminate\Http\Request;

RateLimiter::for('otp', function (Request $request) {
    return [
        Limit::perMinute(5)->by($request->input('phone', $request->ip())),
        Limit::perMinute(20)->by($request->ip()),
    ];
});

Déploiement Production

  1. Définir MSG91_AUTH_KEY, MSG91_WIDGET_ID et MSG91_SENDER_ID comme secrets dans le pipeline CI/CD GitHub Actions (jamais en clair dans le dépôt).
  2. Vérifier que le domaine lovmy.fr sert l'API exclusivement en HTTPS (certificat Let's Encrypt renouvelé automatiquement sur le VPS Hostinger).
  3. Activer les logs applicatifs (otp channel) avec rotation et purge automatique après 30 jours.
  4. Configurer une alerte de supervision sur le solde MSG91 (Add Funds) pour éviter toute interruption d'envoi de SMS.
  5. Exécuter php artisan config:cache et php artisan route:cache après chaque déploiement.
  6. Valider en staging (dontmove.app) avec le Widget de test avant bascule en production.
